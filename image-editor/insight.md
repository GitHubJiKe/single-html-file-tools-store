# 需求洞察报告：单文件图片编辑工具

## 需求核心本质解析

提供一个轻量级、零配置、本地化的单文件图片标记工具，满足用户对隐私保护和快速简单标记（文字、Emoji）的高频操作需求。

## 真/伪需求诊断结果

**诊断结果：真需求**

- **隐私性**：图片往往包含隐私信息，用户排斥上传到云端服务器。本工具基于本地 Canvas API，数据不出浏览器。
- **即时性**：通过单文件运行，省去了安装软件或打开大型在线平台的加载时间。
- **功能聚焦**：针对“加字、加 Emoji”这两个最核心的快速分发场景进行优化。

## 现有市场方案对照表

| 产品名                 | 优势                 | 劣势                                   | 与设想方案对比                             |
| :--------------------- | :------------------- | :------------------------------------- | :----------------------------------------- |
| **Canva / Photopea**   | 功能极其强大，专业级 | 需要联网、操作复杂、资源占用高         | 设想方案更轻量，秒开即用                   |
| **TinyWow / iLoveIMG** | 浏览器内运行         | 需要上传文件到云端，存在隐私风险和延迟 | 设想方案是纯本地处理，更安全、更快速       |
| **系统内置画图/预览**  | 无需下载，系统原生   | 功能单一，Emoji 插入不直观，UI 平庸    | 设想方案提供更现代的 UI 和更便捷的 UI 交互 |
| **GitHub 开源小工具**  | 极简、开源           | 大多缺乏 UI 设计，交互逻辑简陋         | 设想方案通过 `ui-ux-design` 注入高级美感   |

## 市场真空态判定

**是**。在“极致设计感”与“单文件本地化”这两个维度的交集处，目前缺乏令人惊艳的开源方案。

## 最终建议与行动指南

**建议开发**。

- **核心差异化**：注入 UI/UX Skill 的高级审美，集成流畅的多图层/元素交互体验。
- **技术路线**：坚持“三不原则”（不换行、不跨文件、不加构建），锁死纯 Canvas 实现。

## 后续演进建议

1. **交互增强**：支持元素的自由拖拽、缩放、旋转。
2. **字体集成**：通过 CDN 在线加载 Google Fonts，提升视觉上限。
3. **状态持久化**：支持将简单的编辑状态暂存在 URL 或 localStorage 中。
